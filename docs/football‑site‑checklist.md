# 足球数据网站项目风险&合规检查清单
> 项目概况：双语中英文足球数据网页，国内为主、海外可访问；部署香港/新加坡海外服务器，使用.com域名 + Cloudflare CDN，无需ICP备案。
> 用途：用于AI进行项目整体风险扫描、代码与架构检查，覆盖域名、服务器、网络架构、版权、数据API、安全、法律合规。

## 一、域名相关检查项
- [ ] 域名后缀选用 `.com` 为主域名；不将 `.cn` 作为主站，`.cn`仅做保护并301重定向至主域名
- [ ] 域名在国内注册商（阿里云/腾讯云）完成**域名持有者实名认证**
- [ ] 明确区分：域名实名认证 ≠ ICP备案；本项目服务器部署香港/新加坡，**不需要ICP备案**
- [ ] 域名DNS Nameserver修改为Cloudflare，不在原注册商处维护解析A记录
- [ ] 域名名称、路径、接口路径不使用联赛商标词：`fifa、csl、premier、laliga`等，规避商标侵权
- [ ] 域名主体避免使用横杠、数字
- [ ] 注意：国内注册商下购买的.com，域名whois隐私保护有可能被强制关闭，实名信息可被查询，运营主体可追溯

## 二、服务器与网络架构（香港/新加坡VPS）
- [ ] 服务器地域确认：中国香港 / 新加坡，**不是中国大陆内地机房**
- [ ] 实例已分配公网IPv4；安全组入站仅放行：`22(SSH)、80、443`，其余端口全部关闭
- [ ] 系统：Ubuntu 22.04，使用Nginx作为Web服务
- [ ] SSH安全加固：禁用root密码登录，使用SSH密钥登录；可选优化：修改SSH端口降低脚本扫描风险（仅辅助防护，不能替代密钥登录）
- [ ] Nginx关闭版本泄露 `server_tokens off;`
- [ ] Nginx关闭目录浏览 `autoindex off;`，防止泄露目录文件
- [ ] 数据库不对外开放公网端口，仅允许本机/内网访问

### Cloudflare配置
- [ ] DNS A记录 `@`、`www` 填写源站服务器公网IP，**云朵为橙色Proxied代理模式，隐藏源站真实IP**
- [ ] SSL/TLS加密模式设置：`Full (strict)`
  > ⚠️重要：Full(strict) **不允许源站使用自签名证书**，源站必须部署受信任CA证书（Let’s Encrypt）
- [ ] Page Rules开启 `Always Use HTTPS`，全部HTTP强制跳转HTTPS
- [ ] 配置301跳转，统一不带www主域名
- [ ] `/api/*` 接口路径设置**绕过缓存**，防止比赛比分、统计数据返回旧缓存
- [ ] 开启HTTP/2提升页面加载性能
- [ ] 设置安全HTTP响应头：X-Frame-Options、X-Content-Type-Options、Referrer-Policy，防止点击劫持、MIME嗅探、信息泄露
- [ ] 可选：开启 Bot Fight Mode抵御恶意爬虫扫描；注意：免费版存在小概率误拦截国内正常访客风险，上线后观察访问日志

### Nginx配置
- [ ] 配置 `set_real_ip_from`，**导入完整Cloudflare IPv4+IPv6地址段；CF IP段会定期更新，建议脚本自动拉取更新配置，不要硬编码少量IP**，获取用户真实客户端IP，避免日志全部显示CF节点IP
- [ ] SPA路由兼容 `try_files $uri $uri/ /index.html;`
- [ ] API接口添加 `no-store` 不缓存响应头

> 安全提醒：源站公网IP不要随意对外泄露，禁止直接ping源站IP。

## 三、后端安全（API密钥防护）
- [ ] ❗禁止将第三方API Key暴露在前端JS代码
- [ ] 全部第三方足球API请求，通过自建后端服务中转代理
- [ ] 后端服务合理配置CORS跨域策略，避免浏览器跨域报错，不配置通配符*过度开放
- [ ] API密钥禁止打印、输出到应用日志、Nginx访问日志，避免密钥泄露
- [ ] 实现请求缓存逻辑：
    - 实时比分接口缓存：30‑60秒
    - 积分榜、联赛统计缓存：5‑15分钟
- [ ] 增加API配额监控，监控第三方API剩余调用额度，避免配额耗尽导致接口全部失效
- [ ] 第三方API调用失败时要有降级兜底，不直接把原始后端错误栈输出给前端浏览器

## 四、数据源 & API合规检查（重点版权风险）
> 法律要点：
> 1. 单纯单条最终比赛比分属于客观事实，不受版权保护。
> 2. 人工整理加工后的：完整比赛事件流、xG预期进球、球员高阶统计、整套整理后的数据库集合，属于汇编作品，受著作权法、反不正当竞争法保护。
> 3. 即使目标网站页面公开，暴力高频爬虫抓取，也存在不正当竞争法律风险。
> 4. 即便购买付费API获得数据使用权：**数据可以使用，但禁止直接复制对方HTML/CSS与完整页面布局；业务逻辑可以参考，前端UI必须自行开发**。

### ❌严禁使用
- [ ] 禁止逆向爬取：懂球帝、雷速、球探、500彩票网、Sofascore、Flashscore内部前端JSON接口
- [ ] 禁止部署Github上直接爬取上述网站的爬虫项目对外公开服务（代码能跑不等于合法）
- [ ] 禁止任何形式展示赔率、亚盘、欧赔、赔率历史、盘口走势（版权+博彩双重高危红线）
- [ ] 禁止直接盗链第三方网站队徽、球员头像图片资源

### ✅可选合规API清单
1. **football-data.org v4**
    - 免费层：10次/分钟；无每日上限；无实时live比分，无比赛事件流；**免费协议不允许任何公开互联网站点使用，仅限完全本地、不对外暴露的开发调试**
    - 付费：LiveScores 12€/月；Deep‑Data 29€/月起；付费后获得商用授权
2. **API‑Football(api‑sports.io)【个人上线优先推荐】**
    - 免费层：100次/天；仅限本地开发调试；**只要部署到公网、互联网其他用户可以访问，无论是否投放广告，即视为商用场景，必须升级付费套餐**
    - Pro套餐：19美元/月，7500次请求/天，✅完整商用授权，支持实时比分、阵容、比赛事件
3. **TheSportsDB**
    - 免费无硬性限流；无实时比分，更新较慢；商用需要向官方申请授权
4. **Open‑Football(football.json)**
    - 离线JSON/CSV数据集，本地导入使用；无在线API接口；仅历史赛果；可自由使用

> 上线规则：
> - 仅完全本地开发原型，不对外网暴露：可以使用API免费版
> - 公网上线（无论是否投放广告）：严格阅读服务商服务协议，达到商用条件必须购买对应付费套餐
> - 页面底部建议标注数据来源声明

### 静态资源合规
- [ ] 队徽、球队图标优先使用开源SVG队徽库，不要直接爬取商业媒体网站图片
- [ ] 不要直接抓取使用球员肖像头像，规避肖像权风险

## 五、法律与内容合规
> 重要：服务器部署香港/新加坡 = 免除ICP备案手续，**不等于免除中国法律约束**；运营主体为中国公民，面向国内网民访问，网站内容必须遵守中国相关法律法规。
- [ ] 网站内容不包含色情、赌博、政治敏感、盗版侵权内容
- [ ] 不提供任何博彩相关跳转、广告、暗示内容
- [ ] 使用第三方数据，页面底部标注数据来源声明
- [ ] 禁止高频暴力爬虫抓取公开网页，避免不正当竞争风险

- [ ] 确认所有网络请求均为HTTPS，无混合内容报错

## 七、风险总结（供AI重点扫描）
1. 🔴最高风险：直接逆向抓取商业体育网站内部接口对外提供服务，引发著作权、反不正当竞争起诉风险。
2. 🟠次高风险：API Key泄露到前端、输出到日志，第三方服务商账户被盗刷耗尽配额；数据库直接暴露公网端口。
3. 🟡业务坑点：API实时接口没有配置绕过缓存，CDN返回旧比分旧统计数据。
4. 🟡配置坑：
   - Cloudflare Full(strict)使用自签名证书，造成回源失败
   - Cloudflare IP段不全/长期不更新，拿不到真实访客IP
5. 🟡协议误区：不是只有投放广告才算商用；部分API协议：只要公网可访问即判定商用。
6. 🟢认知误区：海外服务器免ICP备案 ≠ 可以发布侵权、违法内容。
7. 🟢UI风险：拿到合法数据，但直接复制第三方网站页面布局样式，带来界面著作权风险。
