## 一、背景与目标

第一批（2026-08-05）完成三个表格页（球员/排行榜/对比）移动卡片化 + 头部搜索层，设计文档写明「第二批（ScheduleView / TeamDetailView / PlayerDetailView / FavoritesView / HomeView 二次优化）验收后另起 spec」。

第二批摸底结论：这四个页面本就是自适应网格出身，375px 下**无阻塞性问题**；唯一有真问题的是收藏夹页——

1. **样式脱节**：仍是旧明暗双主题风格（蓝页签、红删除字、双色标题），与全站暗色调格格不入
2. **布局拥挤**：球队条目一行里名字 + 导出日历按钮 + 删除按钮抢宽度
3. **信息缺失**：看不出条目属于哪个联赛，无队徽

目标：收藏夹页重写为全站统一暗色卡片风格（移动与桌面同时受益）；其余四页逐页复查，只修复查中发现的真问题。

**真问题定义**：溢出、横滑、点按打架、内容看不见、样式破碎。末行不对齐、留白不均等美观问题不算真问题，不动。

## 三、收藏夹页重设计（样式稿 B′）

### 单行卡布局

```
[队徽/星标圆] 名字 …… [联赛徽章]  [日历] [删除]     ← 球队行
[★ 圆牌]     名字 …… [联赛徽章]         [删除]     ← 球员行
```

- 名字点击跳详情（沿用现状）；按钮区独立，不触发跳转
- **布局规则**：徽章与按钮永远完整显示（`flex-none`），名字占剩余空间（`flex-1 truncate`）。英文模式长队名（如 Wolverhampton Wanderers）被截断是**预期行为**，不算缺陷——与赛程卡（MatchCard）处理一致

### 无编号遗留条目

收藏数据结构中 `teamId` / `athleteId` 为可选字段（早期存入的条目可能无编号）。无编号条目渲染为：**名字 + 联赛徽章，无队徽、无按钮、不可跳转**（继承现有行为），并列入单测。

### 页面结构

- 页标题改各联赛页统一样式（参照 ScheduleView 标题；现样式为旧风格残留）
- 页签（球队/球员 + 计数）保留，样式改暗色圆角钮；**下划线用中性浅色**——本页无联赛上下文，不能用联赛色变量
- 空态引导（EmptyState）保留
- 删除行为不变：即删 + toast，无确认弹窗
- 容器 `max-w-3xl` 保留

## 四、组件分解

### 1. `src/components/favorites/FavoriteRowCard.vue`（新）

**Props**：

```ts
defineProps<{
  kind: 'team' | 'player'
  name: string
  league: LeagueSlug
  teamId?: number      // 球队条目（可缺）
  athleteId?: number   // 球员条目（可缺）
  team?: Team          // 已解析的球队档案；缺省 → 首字圆牌兜底
}>()
```

**Emits**：`go`（名字点击）/ `remove`（删除）

**编号字段的用途**：`teamId` / `athleteId` 供卡内判定按钮有无——缺编号的遗留条目不渲染任何按钮（降级渲染），跳转由父级响应 `go` 后自行组装。

**视觉**：
- 队徽：TeamLogo 组件 24px；无档案时兜底圆牌 = 联赛色背景 + 队名首字母
- 球员：黄色星标圆牌（收藏无球员头像数据，不假造）
- 联赛徽章：`leagueInfo` 的中/英文名 + 联赛色透明底圆角小标
- 紧凑钮：「日历」（仅球队行且有编号时渲染——**直接内嵌 ExportCalendarButton 紧凑变体**，拉数据/下载/提示整链在按钮组件内闭环，卡片不发导出事件）+「删除」

### 2. `ExportCalendarButton`（改）

加 `compact?: boolean`（默认 `false`）：
- `false`：现有文案「导出赛程到日历 / Export to Calendar」与现有样式——球队详情页用法不受影响
- `true`：新文案键 `cal.exportShort`（中「日历」/ 英「iCal」）+ 紧凑样式

导出逻辑（拉 10 个月赛程 + 生成日历文件 + 下载 + 提示）一行不动。

### 3. `FavoritesView`（重写）

- **队徽解析**：收集有球队收藏的联赛集合 → 并行调**球队档案库的 `ensure()`** → `teamById` 取队徽
  - ⚠️ 不用 `ensureLeague`：该函数副作用会把入参联赛设为"当前联赛"（全站主题色联动），收藏夹是跨联赛页，会搅乱联赛上下文；档案库 `ensure()` 只拉 meta + teams 两个小文件，24 小时缓存、内存去重、无副作用
  - 只为**有球队收藏**的联赛预载（球员条目用不着队徽）
- 页签切换、跳转、删除处理沿用现有逻辑

## 五、数据流 / 错误处理 / 状态管理

**数据流不变**：收藏仍走用户数据存取（localStorage），不新增存储。

新增的球队档案拉取为**尽力而为**：并行 + 逐个捕获吞错，失败只影响队徽显示（落兜底圆牌），不影响列表渲染，不新增错误态、不弹错误提示。

## 六、i18n

- 新增键：`cal.exportShort` = { 中：日历，英：iCal }
- 复用键：`fav.remove` / `fav.removed` / `fav.title` / `fav.teams` / `fav.players` / `fav.empty*`；联赛名走 `leagueInfo`
- 红线：**不许新增硬编码文案**（第一批验收教训，两处硬编码批次清理才还清）
