# 球队详情页主副色主题 设计稿

> 性质：球队详情页（`TeamDetailView`）视觉主题化
> 方向：**旗面式（强主题）**——页头整块渐变旗面 + 下方主色点缀（视觉伴侣 2026-08-13 两轮对比，总司令裁定）
> 实现路径：**复用 `bannerTheme()` + CSS 变量**（总司令裁定）
> 关联：与子项目 2.0 主队队旗卡（`MyTeamCard`）同一套视觉语言与纯函数

## 一、背景与目标

球队详情页目前是无主题的中性深色：页头一行（队徽 + 名字 + 缩写/场馆 + 三按钮）、战绩 7 格、阵容分组，全程 `white/10` 边框 + `slate` 文字，**完全没用到球队自己的主副色**。

首页订阅卡（子项目 2.0）已把"主色上旗面、副色做斜纹与细线"跑通，且沉淀了纯函数 `bannerTheme()` 处理颜色兜底。本设计把同一套视觉语言落到球队详情页，让用户进入某队主页时立刻有"这是这支球队的地盘"的归属感。

**目标**：球队详情页体现该队主副色主题，复用既有机制，不引入新的取数与新的颜色算法。

**非目标**：不改球员详情页、比赛弹窗、其他联赛页的主题。

## 二、决策过程（视觉伴侣对比，均经总司令裁定）

| 轮次 | 问题 | 结论 |
|---|---|---|
| 1 | 主题力度三选（A 旗面横幅 / B 克制点缀 / C 组合） | 总司令指出 A、C 几乎一样——**旗面才是主角**，合并 |
| 2 | 页头要不要大块旗面（旗面式 vs 点缀式，下半身故意相同） | **选方向一：旗面式（强主题）** |
| 3 | 实现路径 | **选路径一：复用 `bannerTheme()` + CSS 变量** |

**被否的路径**：
- 抽共享"队旗头"组件：订阅卡旗面是"排名徽章 + 点击跳详情"，详情页旗面是"场馆 + 按钮"，内容差异大，硬合并拖出一串参数开关，两处用法撑不起抽象。
- 行内样式直写颜色：丢掉 `bannerTheme()` 的明度兜底，白主色球队会白底白字，等于把订阅卡 2.0 踩过的坑再踩一遍。

## 三、视觉规格

详情页从上到下四块，改动集中在前三块。

### 3.1 返回钮
不动，留在最上面。

### 3.2 页头：从"白底行"换成"旗面"（核心改动）
- 整块渐变：`主色 → 主色混 30% 黑`，约 112° 角，叠副色斜纹——与订阅卡同一套（`bannerTheme` 的 `from`/`to`/`stripe`）。
- 内容横排：64px 队徽 + 大队名 + 一行小字（缩写 · 球场 · 城市）。
- 文字色由 `bannerTheme` 的 `darkText` 自动定（深主色→白字，白主色→深字）。
- 旗面下缘 3px 细线（pin）：副色 → 主色渐变，订阅卡同款。

### 3.3 按钮行
订阅 / 收藏 / 导出三按钮挪到旗面正下方，按钮样式本身不动。

### 3.4 战绩格与阵容：上点缀
- 战绩 7 格：左侧 3px 主色边条（`--accent`）；"积分"格单独主色浅底 + 主色数字（订阅卡 `stat-pts` 同款）；胜绿负红语义色（同订阅卡 `val-w`/`val-l`，现为白字，属本次顺带统一）。
- 阵容总标题：主色下划线；四个位置分组小标题（门/后/中/前）改主色。

**不动**：`TeamSquad` 球员行本体、`DataLoading`/`DataError`、路由逻辑。

## 四、数据流与兜底

**零新增请求**——详情页本就通过 `ensureLeague` 载入球队包，主题从已有数据算：

1. `team`（现成 computed，按路由取队）→ `bannerTheme(team.color, team.alternateColor)` 算出整套主题 → 以 CSS 变量挂到**包住旗面 + 战绩 + 阵容的外层容器**（战绩格与阵容分组要用 `--accent`，故变量挂高一层，不只挂旗面）。
2. 变量清单照抄订阅卡：`--flag-from` / `--flag-to` / `--flag-stripe` / `--pin-from` / `--pin-to` / `--accent` / `--flag-text`，样式类可与订阅卡互抄。
3. **换队自动变色**：同联赛切队，球队包已在内存，主题瞬时换；跨联赛切队，`ensureLeague` 拉包期间显示现有加载骨架，包到即出旗面——无需额外处理。
4. **兜底两层**：
   - 主色为空（现数据不存在，纯防御）→ 退回联赛色，同订阅卡 `flagTeam`。
   - 副色为空或与主色分不开 → `bannerTheme` 内部已有退路（斜纹用黑色半透明、细线用强调色），不用管。

**数据核验（2026-08-13）**：六联赛 96 队全部有 `color` 与 `alternateColor`，抓取脚本里的空值分支只是防御代码。

## 五、测试策略（先写测试再写实现）

新建 `tests/views/TeamDetailView.test.ts`（该页目前无测试文件）：

1. **主题上页**：注入红色球队 → 断言外层容器样式含 `--flag-from` 且为主色值、`--accent` 在位（订阅卡同款断言）。
2. **白主色深字**：注入白主色球队 → 断言 `--flag-text` 为深色值（白底配深字，防白底白字）。
3. **点缀落位**：战绩"积分"格与阵容分组标题吃到 `--accent`。
4. **基本盘**：队名、战绩格、阵容分组照常渲染——主题改造不伤原有结构。

**回归门槛**：全套测试绿 + typecheck + build 过。

## 六、手测清单（待总司令批准浏览器）

天津（紫）、阿森纳（红）、热刺（白主色）三队详情页——桌面 + 375px 移动各过一遍，看：旗面渐变与斜纹、战绩边条与积分格、阵容分组主色、深字模式、换队变色。

## 七、不做的事

- 不抽共享"队旗头"组件（内容差异大，两处撑不起抽象）。
- 不改球员详情页 / 比赛弹窗 / 其他页面的主题。
- 不动球队数据抓取与颜色数据本身。
- 不新增取数请求。
