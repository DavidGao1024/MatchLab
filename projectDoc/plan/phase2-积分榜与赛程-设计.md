## 一、任务与边界

**目标**：能切换联赛，看积分榜和赛程；首页开场即比赛日。

**铁约束**：
- 现有数据文件结构与抓取脚本一律不动，本期纯消费 `public/data/` 现成 JSON
- 前端取静态数据一律走 `import.meta.env.BASE_URL` 前缀（线上 404 教训，禁止绝对路径）
- 架构按蓝图 §3/§6 搭，不另起炉灶

**明确不做**：比赛详情弹窗（Phase 3）、球队页/球员页/排行榜（Phase 4/5）、图表（Phase 6）、主客场战绩拆分、按轮次浏览、积分榜行点击跳转、球场名翻译、蓝图 §3 的独立 MobileNav 组件（移动端导航并入响应式处理：联赛页签横滑 + 卡片整张可点）。

## 二、需求决策记录（2026-07-27 定）

| 决策点 | 结论 |
|---|---|
| 视觉方向 | 转播图形风：深色底 + 主题色随联赛切换（英超紫/西甲橙/意甲蓝/德甲红/法甲青，取自 `leagues.json` 的 color 字段） |
| 赛程数据供给 | 混合模式——过往月份读静态 `matches/{YYYY-MM}.json`；当前自然月浏览器直连 ESPN site.api 拿实时比分 |
| 首页定位 | 联赛选择器 + 上轮战报（不做大标题口号式首页） |
| 积分榜配置 | 标配（区带色带 + 队徽 + 全部积分列）+ 近 5 场形势列 + xG/xPts 开关；不做主客场拆分 |
| 赛程版式 | 日期分组 + 横向对阵卡片（主左客右、比分压中、胜者高亮） |
| 语言 | 默认中文，中/英可切换；96 队中文译名内置；球场名保持英文 |
| 交流语言 | 永远使用中文交流（已写入 CLAUDE.md，2026-07-27 立规） |

## 三、总体架构与数据流

浏览器只拿两类东西（项目总纲）：

```
静态 JSON（BASE_URL 前缀）
├─ leagues.json（实测 1.4KB）          ← 应用启动
├─ {league}/meta.json + teams.json    ← 切换联赛时（队徽/颜色全站复用）
├─ {league}/standings.json（实测 5KB）  ← 进积分榜页，缓存 1 小时
├─ {league}/xg/standings.json（实测 394–490KB/联赛，含逐场历史） ← 按下 xG 开关才加载，只取赛季汇总字段、不碰 history，缓存 24 小时
└─ {league}/matches/{YYYY-MM}.json    ← 过往月份赛程，缓存 1 小时

ESPN site.api 直连
└─ scoreboard?dates=YYYYMM01-YYYYMMDD&limit=200 ← 仅当前自然月，实时比分（limit 必带，蓝图 §6.3 同款，防默认分页截断丢比赛）
```

**关键规则**：

1. **活/死数据分界 = 自然月**：当前月 → ESPN 直连，只存内存不落本地缓存；页面上有"进行中"比赛时每 60 秒自动刷新（切换月份或数据刷新后重新评估"有无进行中比赛"，决定续停），组件卸载即停。其他月份 → 静态文件
2. **月份清单由赛季号推导**：`season: "2025"` → 2025-08 至 2026-05 共 10 个月（五大联赛统一 8 月开 5 月收），不改抓取脚本、不探活。某月取数失败或 0 场 → 空场提示
3. **默认月份**：当前自然月若在 8 月至次年 5 月之间 → 默认当月；否则（6/7 月休赛期）→ 默认 5 月收官月
4. **直播断线兜底**：当月 ESPN 直连失败 → 退回同月静态快照文件（赛季内由 Actions 每日生成），挂提示"直播暂不可用，展示 HH:mm 快照数据"；快照文件也不存在时（如休赛期的 6/7 月，仓库里根本没有当月文件）→ 空场提示 + 引导跳最近有数据的月份
5. **近 5 场形势**：积分榜页只拉最近两个自然月的赛程文件现场计算（实测约 50KB：4 月末 21KB + 5 月末 29KB）；赛季初只有一个月就用一个月
6. **路由**（hash mode）：`/` 首页、`/:league`（重定向到 `/:league/standings`）、`/:league/standings`、`/:league/schedule`、`/:league/schedule/:month`；`:league` 不是五大联赛 slug 之一 → 重定向 `/`；`:month` 须为 YYYY-MM 格式且在赛季月份清单内，否则回落默认月份
7. **xG 合并**：映射文件实际结构为 `{ description, updateTime, count, map }`，真正的映射表在 `map` 字段（26 条，方向 Understat 队名 → ESPN 队名）；对不上的行 xG 列留空，不报错。**每行只取 4 个字段：team（合并键）+ xG + xGA + xpts；文件里的逐场 history、deep、npxG 等大宗字段一律丢弃，不进缓存不进状态**

**首屏账本**（实测数据，进英超积分榜）：联赛列表 1.4KB + meta/teams 18.4KB + 积分榜 5KB ≈ **25KB**，比蓝图 §5 预算线（65KB）更宽裕。首页首访：5 联赛积分榜 24KB + 默认联赛末月赛程 29KB ≈ **53KB**。xG 开关为额外 394–490KB 下载开销（五联赛实测区间；入缓存的只有汇总字段，实占几 KB），故必须懒加载。

**导航行为（LeagueTabs）**：顶栏联赛页签点击 = 切换联赛但**留在当前页面类型**（积分榜上切联赛还是积分榜，赛程页上切还是赛程页）；唯独在首页点页签 → 进该联赛积分榜（与点联赛卡一致）。

### 首页（开场即比赛日，确认稿见文首 mockup 路径）

自上而下三段：

1. **上轮战报转播带**（MatchdayStrip）："上轮" = 最近一个有完赛的比赛日——从默认月份文件往前扫（当月没有已完赛比赛就回看上月文件，**最多回看 2 个月份文件**，再没有就不出战报带、首页只剩联赛板块）。默认焦点联赛 = 英超（eng.1），顶栏页签随之高亮。**选场规则（确定性，无魔法）**：一个比赛日场次多于 4 时，按"① 涉及积分榜榜首球队的比赛 ② 涉及榜二球队的比赛 ③ 剩余名额按开球时间从早到晚补"取 4 场（去重）。**焦点高亮规则**：4 场中涉及榜首球队的那场打焦点标记（收官日自然就是夺冠战；查不到榜首参与的比赛则不标记）。展示为桌面端横排 4 卡、移动端竖排，日期徽章 + "查看完整赛程"入口。背景 = 联赛品牌色光晕 + 淡球场标线纹理
2. **联赛板块**（不对称布局）：英超焦点大卡（LeagueCard，5 行迷你榜——列与确认稿 mockup 一致：名次 / 队名 / 胜 / 平 / 负 / 积分，不含进失球 + 色带图例 + "进入英超"入口，占左侧 7 成宽）+ 其余四联赛 2×2 小卡（各带榜首两队 + 积分 + 队伍/球员规模），点击进入该联赛积分榜。首页数据**并行抓取**（联赛列表 + 5 份积分榜 + 末月赛程一把 Promise.all，不串行等待）；"查看完整赛程"链接精确到战报所在月份（`/#/{league}/schedule/{战报月份}`）。**与 mockup 的一处出入（施工以本规格为准）**：确认稿里球场名是手工汉译的演示文案（安菲尔德、伊蒂哈德等），本期不做球场翻译，页面统一显示英文球场名
3. **页脚状态条**：管线心跳灯 + "自动管线每日 14:00（北京时间，= 工作流 UTC 06:00）刷新 · 数据快照日期（取 leagues.json 的 updateTime）· 来源 ESPN / Understat"

### 积分榜页

- 页头：联赛中文名 + 赛季 + 数据更新时间（取 standings.json 的 updateTime 字段，经 useTimezone 转本地时间显示，不裸出 ISO 串）+ xG 开关（默认关；开关状态只存会话内，刷新归关）
- StandingsTable：列 = 名次 / 队徽+队名 / 赛 / 胜 / 平 / 负 / 进 / 失 / 净 / 积分（大数字）/ 近 5 场形势 /（xG、xGA、xPts 开关控制显隐）
- **区带配置**（constants.ts 每联赛各写一份，规则不通用）：英超/西甲/意甲（20 队）= 前 4 欧冠（联赛品牌色条）+ 第 5 欧联（橙条）+ 后 3 降级（红条）；德甲（18 队）= 前 4 欧冠 + 第 5 欧联 + 第 16 降级附加赛（橙红条）+ 第 17/18 直接降级（红条）；法甲（18 队）= 前 4 欧冠 + 第 5 欧联 + 后 2 直接降级（无附加赛）。区带之间虚线分隔，表尾小图例
- FormDots：胜绿/平灰/负红圆点，最近一场在最右，悬停显示对手 + 比分；不足 5 场按实际场数出点；回看窗口内该队无比赛（如赛季首轮）→ 占位短横线
- 交互：行悬停右移 + 联赛色边；表头吸顶；全列最多 14 列（含形势 + xG 三列），窄于 1200px 的视口表格容器整体横滑；移动端"名次+队名"列固定、数字列横向滑动。**表格按数据里的 rank 字段直出，不做客户端排序**——数据本身就是最终排序，排序 UI 属于过度设计

### 赛程页

- MonthStrip：10 个月份页签横排；赛季内（8 月至次年 5 月）当前月挂红点"LIVE"，休赛期不挂
- MatchList 按**数据日期（UTC 日期）分组**（组头如"8月16日 · 周六 · 6场"）——保证任何时区的用户看到的分组一致、可分享；时间显示换算为用户本地时区
- MatchCard：主左客右、比分压中（记分牌字体）、胜者高亮；未开赛显示本地时间 + "VS"，本地日期越过组头日期时加"次日"前缀（如"次日 00:30"）；进行中显示分钟数 + 脉冲红点
- 空场/休赛期：该月无比赛 → 空场提示；6/7 月 → "赛季已收官，展示最终数据"横幅

### 公共件

- TeamLogo：队徽图 + 懒加载，失败退化为球队主色圆牌 + 首字母；深色背景优先用 teams.json 里的 logoDark 字段（深色版队徽，数据里现成的）
- DataLoading：骨架屏（表格行/卡片两种形状）
- DataError：说明 + 重试按钮；局部失败不连坐整页

## 五、数据层

### 四个 Pinia store

| store | 状态 | 缓存策略 |
|---|---|---|
| app | 当前联赛（与路由同步）、语言（默认 zh，持久化） | — |
| teams | 每联赛 meta + teams；按球队 ID 快查（队徽/主色） | 会话内不过期 |
| standings | 正榜 / xG（懒加载）/ 近 5 场形势（最近两月赛程算） | 正榜 1h，xG 24h |
| matches | 过往期静态缓存 + 当月内存态；ESPN 响应归一化为 Match 模型 | 静态 1h，当月不落盘 |

### 四个 composable

- `useJsonFetch`：静态数据唯一入口——BASE_URL 前缀、本地缓存（键格式 `matchlab:v1:{season}:{path}`——**赛季号入键**，八月赛季更替时旧缓存自动作废，不用等 TTL；缓存写入格式 `{ data, ts }`，读取按 TTL 验期，沿用蓝图 §6.2 模式；缓存读出后 JSON 解析失败按未命中处理，不抛错）、失败抛给 DataError
- `useEspanFetch`：ESPN site.api 封装（当月 scoreboard；详情接口为 Phase 3 预留位）；**响应统一归一化**：比赛状态收敛为 pre/in/post 三态（与静态文件口径一致），页面层永不接触 ESPN 原始结构——将来接口变脸只改这一个文件
- `useLeague`：监听路由 `:league` 变化 → 校验 → 拉 meta+teams → 写 appStore；非法参数打回首页
- `useTimezone`：UTC ISO → 用户本地时区；中文格式"8月16日 · 周六 22:00"，英文格式"Aug 16 · Sat 22:00"；"次日"前缀的判定标准 = 本地日期越过比赛的 UTC 日期（即组头日期），两种语言统一逻辑

**加载顺序契约（深链安全）**：`useLeague.ensure(league)` 幂等——缓存命中立即返回，未命中才拉 meta+teams；**同一联赛的并发调用复用同一个在途请求**（防用户快速连切联赛重复抓取）。App.vue 监听路由 league 参数先行调用；三个页面视图（StandingsView / ScheduleView / HomeView）在 setup 里先 await 这个调用、再取自己的数据。保证直接打开任意深层路由（如分享链接 `/#/ita.1/standings`）时，队徽与主色数据必定就位。**过期响应防护**：页面视图各自维护请求序号，异步响应回来时若当前联赛/月份已切换，丢弃该响应不渲染（防 A 联赛的慢请求覆盖 B 联赛的新数据）。

### 类型与文案

- `types/models.ts`：Match / MatchTeam / StandingRow / XgRow / Team / LeagueInfo（对齐蓝图 §9）
- `types/static.ts`：静态文件外壳（source / updateTime / league / count）
- `types/espn-site.ts`：scoreboard 原始响应类型
- `utils/i18n.ts`：轻量字典方案（不引第三方库）；TEAM_ZH 内置 96 队标准中文译名；联赛中文名直接取数据里的 nameZh。英文模式下队名/联赛名直接用数据原始英文字段（ESPN displayName），无需另备英文字典。**一切界面文案过字典**——包括错误提示、空场提示、休赛期横幅、骨架占位文字，组件里不许硬编码中文（否则英文模式半拉子汉化）

## 六、视觉系统

- **背景三层**：深藏青底 `#0c101b` + 极淡球场标线纹理（中圈/中线）+ 页面顶部当前联赛品牌色光晕；切联赛光晕平滑变色（CSS 变量 + 过渡）
- **字体两副面孔**：比分/积分/排名用瘦高记分牌字体（Bebas Neue / Oswald），正文用 IBM Plex Sans + 系统中文字体；数字全部等宽对齐；积分列字号比小统计列大一号。注意 Bebas/Oswald 不含中文字形，中文标题走系统粗体（微软雅黑/苹方）兜底，混排时以中文字体栈收尾
- **配色**：联赛品牌色当主角（选中页签/胜者高亮/区带色条），功能色打下手（胜绿/平灰/负红、降级红、欧联橙、进行中红心跳点）。法甲品牌色近白（#DAE1E6），在深底上直接作高亮色
- **动效**（全原生，不引库；尊重系统"减少动态效果"设置）：积分行悬停右移 + 联赛色边、进行中比分数字弹跳、赛程卡滚动错落浮现、页面切换淡入
- **字体与页面底子**：index.html 加 Google Fonts 链接（配离线降级字体栈）；同步补齐 `lang="zh-CN"`、页面标题（MatchLab · 五大联赛数据查询）、meta description——脚手架期没顾上的门面活
- **主题色机制**：切换联赛时把品牌色写入根节点 CSS 变量 `--league-color`，组件经 Tailwind 4 任意值引用（如 `bg-(--league-color)`、`text-(--league-color)`），全站变色由 transition 统一平滑
- **性能预算**：首屏 JS（Vue + Pinia + Router + 本站代码）gzip 后 ≤ 150KB，本期不引新运行时依赖守死这条线；Google Fonts 加 `font-display: swap` 不阻塞文字渲染；**队徽是页面最大的静态物**（20 张 500px PNG，单张几十 KB，总量可能超过全部 JSON），靠懒加载 + ESPN CDN 公共缓存消化，验收时用浏览器网络面板实测，超标再研究 ESPN 小尺寸图路径

## 七、状态处理

| 情况 | 处理 |
|---|---|
| 加载中 | 骨架屏，绝不白屏 |
| 出错 | 统一错误卡 + 重试；xG 失败 → 开关自动关 + 提示，主表照常 |
| 该月无比赛 | 空场提示 |
| 休赛期（6/7 月） | "赛季已收官，展示最终数据"横幅，月份默认 5 月 |
| 队徽加载失败 | 主色圆牌 + 首字母 |
| 直播断线 | 退回同月静态快照 + 快照时间提示 |

**移动端**：积分榜左列钉住、数字列横滑；其余竖排堆叠；联赛页签横滑；比赛卡片整张可点。

**无障碍（v1.5 补的维度）**：信息不唯颜色论——FormDots 圆点带 aria-label/title（"胜/平/负 + 对手比分"），色带区配有文字图例；积分榜用语义表格（table/th，名次与队名列做行头）；所有可点元素有 focus-visible 焦点环；正文/辅助文字对深底对比度 ≥ WCAG AA（4.5:1，施工时最淡的辅助灰要逐一把关）；动效尊重系统减少动态设置（§六已定）。

## 八、验收标准

1. 首页选联赛 → 直进该联赛积分榜
2. 积分榜全队排序正确（20 队或 18 队按联赛）、带队徽；欧冠/欧联/降级区色带清晰（法甲无附加赛）；近 5 场形势列正确
3. xG 开关生效；xG 数据失败时开关自动关、主表不受影响

## 九、测试策略

- 新置轻量测试设施（vitest），只测五个纯函数：近 5 场计算、时区转换与"次日"判定、xG 行合并（含队名映射）、月份清单推导、按 UTC 日期分组
- 页面层靠 TypeScript strict 类型检查 + 开发服务器人工验收 + 部署后线上实测
- 不写组件快照测试（维护成本高于收益）

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| ESPN 直连偶发失败 | 同月静态快照兜底（见三.4） |
| xG 队名映射缺口（26 条外的差异） | 该行 xG 列留空，不影响主表 |
| 法甲品牌色近白 | 深底上作高亮色使用，不做背景填充 |
| 赛季初（8 月上旬）当月无联赛比赛 | 空场提示 + 引导回看 5 月收官月（上赛季数据不在本仓库，不提供跨赛季浏览） |
| Google Fonts 加载慢/被墙 | 降级字体栈兜底，不阻塞渲染 |
| ESPN 接口响应结构变更（非契约接口） | 归一化集中在 useEspanFetch 一层，改一处全站不受影响；直连失败有静态快照兜底 |
| 隐私模式浏览器无 localStorage | useJsonFetch 缓存读写裹 try/catch，不可用时降级为纯内存缓存，功能不受影响 |
| 队徽图片总体积超过全部 JSON | 懒加载 + CDN 缓存兜底；验收实测超标则改用 ESPN 小尺寸队徽路径 |
