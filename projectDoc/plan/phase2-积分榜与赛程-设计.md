## 一、任务与边界

**目标**：能切换联赛，看积分榜和赛程；首页开场即比赛日。

**铁约束**：
- 现有数据文件结构与抓取脚本一律不动，本期纯消费 `public/data/` 现成 JSON
- 前端取静态数据一律走 `import.meta.env.BASE_URL` 前缀（线上 404 教训，禁止绝对路径）
- 架构按蓝图 §3/§6 搭，不另起炉灶

**明确不做**：比赛详情弹窗（Phase 3）、球队页/球员页/排行榜（Phase 4/5）、图表（Phase 6）、主客场战绩拆分、按轮次浏览、积分榜行点击跳转、球场名翻译。

## 二、需求决策记录（2026-07-27 定）

| 决策点 | 结论 |
|---|---|
| 视觉方向 | 转播图形风：深色底 + 主题色随联赛切换（英超紫/西甲橙/意甲蓝/德甲红/法甲青，取自 `leagues.json` 的 color 字段） |
| 赛程数据供给 | 混合模式——过往月份读静态 `matches/{YYYY-MM}.json`；当前自然月浏览器直连 ESPN site.api 拿实时比分 |
| 首页定位 | 联赛选择器 + 上轮战报（不做大标题口号式首页） |
| 积分榜配置 | 标配（区带色带 + 队徽 + 全部积分列）+ 近 5 场形势列 + xG/xPts 开关；不做主客场拆分 |
| 赛程版式 | 日期分组 + 横向对阵卡片（主左客右、比分压中、胜者高亮） |
| 语言 | 默认中文，中/英可切换；96 队中文译名内置；球场名保持英文 |
| 交流语言 | 永远使用中文交流（已写入 CLAUDE.md，2026-07-27 立规） |

## 三、总体架构与数据流

浏览器只拿两类东西（项目总纲）：

```
静态 JSON（BASE_URL 前缀）
├─ leagues.json（2KB）                ← 应用启动
├─ {league}/meta.json + teams.json    ← 切换联赛时（队徽/颜色全站复用）
├─ {league}/standings.json（10KB）    ← 进积分榜页，缓存 1 小时
├─ {league}/xg/standings.json         ← 按下 xG 开关才加载，缓存 24 小时
└─ {league}/matches/{YYYY-MM}.json    ← 过往月份赛程，缓存 1 小时

ESPN site.api 直连
└─ scoreboard?dates=YYYYMM01-YYYYMMDD ← 仅当前自然月，实时比分
```

**关键规则**：

1. **活/死数据分界 = 自然月**：当前月 → ESPN 直连，只存内存不落本地缓存；页面上有"进行中"比赛时每 60 秒自动刷新，组件卸载即停。其他月份 → 静态文件
2. **月份清单由赛季号推导**：`season: "2025"` → 2025-08 至 2026-05 共 10 个月（五大联赛统一 8 月开 5 月收），不改抓取脚本、不探活。某月取数失败或 0 场 → 空场提示
3. **默认月份**：当前自然月若在 8 月至次年 5 月之间 → 默认当月；否则（6/7 月休赛期）→ 默认 5 月收官月
4. **直播断线兜底**：当月 ESPN 直连失败 → 自动退回同月静态快照文件（Actions 每日生成），挂提示"直播暂不可用，展示 HH:mm 快照数据"
5. **近 5 场形势**：积分榜页只拉最近两个自然月的赛程文件（约 160KB）现场计算；赛季初只有一个月就用一个月
6. **路由**（hash mode）：`/` 首页、`/:league/standings`、`/:league/schedule`、`/:league/schedule/:month`；`:league` 不是五大联赛 slug 之一 → 重定向 `/`；`:month` 须为 YYYY-MM 格式且在赛季月份清单内，否则回落默认月份
7. **xG 合并**：Understat 队名经 `mappings/team-name-map.json`（26 条）转成 ESPN 队名再对行；对不上的行 xG 列留空，不报错

**首屏账本**（进英超积分榜）：联赛列表 2KB + meta/teams 53KB + 积分榜 10KB ≈ 65KB，压在蓝图 §5 预算线内。首页首访：5 联赛积分榜 50KB + 默认联赛末月赛程 80KB ≈ 135KB。

### 首页（开场即比赛日，确认稿见文首 mockup 路径）

自上而下三段：

1. **上轮战报转播带**（MatchdayStrip）："上轮" = 最近一个有完赛的比赛日——从默认月份文件往前扫（当月没有已完赛比赛就回看上月文件）；展示该比赛日的 4 场比赛（桌面端横排 4 卡，移动端竖排），日期徽章 + "查看完整赛程"入口。背景 = 联赛品牌色光晕 + 淡球场标线纹理。焦点战（如夺冠战）高亮标记
2. **联赛板块**（不对称布局）：英超焦点大卡（LeagueCard，5 行迷你榜 + 色带图例 + "进入英超"入口，占左侧 7 成宽）+ 其余四联赛 2×2 小卡（各带榜首两队 + 积分 + 队伍/球员规模），点击进入该联赛积分榜
3. **页脚状态条**：管线心跳灯 + "自动管线每日刷新 · 数据快照日期 · 来源 ESPN / Understat"

### 积分榜页

- 页头：联赛中文名 + 赛季 + 数据更新时间 + xG 开关
- StandingsTable：列 = 名次 / 队徽+队名 / 赛 / 胜 / 平 / 负 / 进 / 失 / 净 / 积分（大数字）/ 近 5 场形势 /（xG、xGA、xPts 开关控制显隐）
- **区带配置**（constants.ts 每联赛一份）：20 队联赛 = 前 4 欧冠（联赛品牌色条）+ 第 5 欧联（橙条）+ 后 3 降级（红条）；18 队联赛 = 前 4 欧冠 + 第 5 欧联 + 第 16 附加赛（橙红条）+ 第 17/18 直接降级（红条）。区带之间虚线分隔，表尾小图例
- FormDots：胜绿/平灰/负红圆点，最近一场在最右，悬停显示对手 + 比分
- 交互：行悬停右移 + 联赛色边；表头吸顶；移动端"名次+队名"列固定、数字列横向滑动

### 赛程页

- MonthStrip：10 个月份页签横排，当前月挂红点"LIVE"
- MatchList 按本地日期分组（组头如"8月16日 · 周六 · 6场"）
- MatchCard：主左客右、比分压中（记分牌字体）、胜者高亮；未开赛显示北京时间 + "VS"；进行中显示分钟数 + 脉冲红点
- 空场/休赛期：该月无比赛 → 空场提示；6/7 月 → "赛季已收官，展示最终数据"横幅

### 公共件

- TeamLogo：队徽图 + 懒加载，失败退化为球队主色圆牌 + 首字母
- DataLoading：骨架屏（表格行/卡片两种形状）
- DataError：说明 + 重试按钮；局部失败不连坐整页

## 五、数据层

### 四个 Pinia store

| store | 状态 | 缓存策略 |
|---|---|---|
| app | 当前联赛（与路由同步）、语言（默认 zh，持久化） | — |
| teams | 每联赛 meta + teams；按球队 ID 快查（队徽/主色） | 会话内不过期 |
| standings | 正榜 / xG（懒加载）/ 近 5 场形势（最近两月赛程算） | 正榜 1h，xG 24h |
| matches | 过往期静态缓存 + 当月内存态；ESPN 响应归一化为 Match 模型 | 静态 1h，当月不落盘 |

### 四个 composable

- `useJsonFetch`：静态数据唯一入口——BASE_URL 前缀、本地缓存（键格式 `matchlab:v1:{path}`，带版本号防脏）、失败抛给 DataError
- `useEspanFetch`：ESPN site.api 封装（当月 scoreboard；详情接口为 Phase 3 预留位）
- `useLeague`：监听路由 `:league` 变化 → 校验 → 拉 meta+teams → 写 appStore；非法参数打回首页
- `useTimezone`：UTC ISO → 用户本地时区；中文格式"8月16日 · 周六 22:00"，跨天"次日 00:30"

### 类型与文案

- `types/models.ts`：Match / MatchTeam / StandingRow / XgRow / Team / LeagueInfo（对齐蓝图 §9）
- `types/static.ts`：静态文件外壳（source / updateTime / league / count）
- `types/espn-site.ts`：scoreboard 原始响应类型
- `utils/i18n.ts`：轻量字典方案（不引第三方库）；TEAM_ZH 内置 96 队标准中文译名；联赛中文名直接取数据里的 nameZh。英文模式下队名/联赛名直接用数据原始英文字段（ESPN displayName），无需另备英文字典

## 六、视觉系统

- **背景三层**：深藏青底 `#0c101b` + 极淡球场标线纹理（中圈/中线）+ 页面顶部当前联赛品牌色光晕；切联赛光晕平滑变色（CSS 变量 + 过渡）
- **字体两副面孔**：比分/积分/排名用瘦高记分牌字体（Bebas Neue / Oswald），正文用 IBM Plex Sans + 系统中文字体；数字全部等宽对齐；积分列字号比小统计列大一号
- **配色**：联赛品牌色当主角（选中页签/胜者高亮/区带色条），功能色打下手（胜绿/平灰/负红、降级红、欧联橙、进行中红心跳点）。法甲品牌色近白（#DAE1E6），在深底上直接作高亮色
- **动效**（全原生，不引库；尊重系统"减少动态效果"设置）：积分行悬停右移 + 联赛色边、进行中比分数字弹跳、赛程卡滚动错落浮现、页面切换淡入
- **字体引入方式**：index.html 加 Google Fonts 链接，配离线降级字体栈

## 七、状态处理

| 情况 | 处理 |
|---|---|
| 加载中 | 骨架屏，绝不白屏 |
| 出错 | 统一错误卡 + 重试；xG 失败 → 开关自动关 + 提示，主表照常 |
| 该月无比赛 | 空场提示 |
| 休赛期（6/7 月） | "赛季已收官，展示最终数据"横幅，月份默认 5 月 |
| 队徽加载失败 | 主色圆牌 + 首字母 |
| 直播断线 | 退回同月静态快照 + 快照时间提示 |

**移动端**：积分榜左列钉住、数字列横滑；其余竖排堆叠；联赛页签横滑；比赛卡片整张可点。

## 八、验收标准

1. 首页选联赛 → 直进该联赛积分榜
2. 积分榜 20 队排序正确、带队徽；欧冠/欧联/降级区色带清晰；近 5 场形势列正确
3. xG 开关生效；xG 数据失败时开关自动关、主表不受影响
4. 切联赛 → 积分榜/赛程联动刷新；同联赛二次进入秒开
5. 赛程页默认落最近有比赛的月份；10 个月份可跳；完赛显比分、未开赛显北京时间 + "VS"
6. 有进行中比赛时每 60 秒自动刷新；直播断线自动退快照
7. 中英文切换生效（联赛名/队名），默认中文
8. 骨架屏、错误重试、空场提示、休赛期横幅四态可见
9. 移动端全流程可用
10. 推送后 GitHub Pages 自动部署，线上实测通过

## 九、测试策略

- 新置轻量测试设施（vitest），只测四个纯函数：近 5 场计算、时区转换格式化、xG 行合并（含队名映射）、月份清单推导
- 页面层靠 TypeScript strict 类型检查 + 开发服务器人工验收 + 部署后线上实测
- 不写组件快照测试（维护成本高于收益）

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| ESPN 直连偶发失败 | 同月静态快照兜底（见三.4） |
| xG 队名映射缺口（26 条外的差异） | 该行 xG 列留空，不影响主表 |
| 法甲品牌色近白 | 深底上作高亮色使用，不做背景填充 |
| 赛季初（8 月上旬）当月无联赛比赛 | 空场提示 + 引导回看上赛季末月 |
| Google Fonts 加载慢/被墙 | 降级字体栈兜底，不阻塞渲染 |
